## 4. 分类效果与实验分析

| 特征数 | KD 准确率 | 暴力准确率 | KD F1 | 暴力 F1 |
| ---: | ---: | ---: | ---: | ---: |
| 2 | 86.80% | 86.80% | 0.0000 | 0.0000 |
| 5 | 85.40% | 85.20% | 0.3178 | 0.2292 |
| 10 | 86.60% | 87.20% | 0.2947 | 0.2889 |
| 15 | 85.60% | 87.20% | 0.3455 | 0.4182 |
| 21 | 85.20% | 83.80% | 0.2745 | 0.2136 |

1. **本次维度越高，KD 树的剪枝效果越弱。**距离计算比例从 2 维的 0.52% 上升到 21 维的 70.39%，中位数耗时比从约 109.40 倍缩小到约 1.15 倍。这里同时改变了输入列的内容，因此不是对“维度本身”影响的完全隔离实验；原剪枝缺陷也可能影响耗时。
2. **准确率不能单独衡量不平衡分类效果。**测试集负类占 434/500 = 86.8%。2 维时两模型全部预测为 0，虽然准确率为 86.8%，但正类召回率为 0，F1 按零分母约定记为 0。
3. **更多特征不一定得到更好分类效果。**本次仅取前若干列，而且未统一数值尺度，不同特征组合的 F1 没有随维度单调上升。当前测试结果用于课堂观察，不能反过来反复选参数后再声称是独立测试效果。
4. **预测分歧需要单独分析。**5、10、15、21 维分别有 49、27、26、11 个样本预测不同。既可能涉及剪枝问题，也可能来自等距离近邻的取舍规则。本次没有逐样本归因，不能把全部分歧都归为同一个原因。
5. **KNN 的“训练”主要是保存数据或建立索引。**KD 树训练略慢于仅存数据的暴力法，但本实验中两者训练耗时都远小于高维的整批预测耗时。

## 5. 教师问题 Q1～Q5 的理解

- **Q1：**`visited` 是建树后累计访问的节点数，一次节点访问对应一次距离计算；它不会在单条预测前自动清零。
- **Q2：**按 `depth % dim` 选择划分维度，排序取中位数，左右子集分别递归构建子树，空集合终止。
- **Q3：**递归访问节点并维护当前最近的 k 个候选，先搜目标所在侧，再依据目标到分割面的距离决定是否回溯另一侧。原实现遗漏“候选不足 k 个”的条件。
- **Q4：**暴力法逐个计算到所有训练点的距离，全部排序后截取前 k 个，再投票。
- **Q5：**每种特征数截取对应列，分别创建 KD 树和暴力分类器，调用 `run_experiment` 完成训练、预测、计时、指标统计，最后对照结果。

## 6. 对代码的改进建议

### 6.1 优先修正 KD 树候选不足时的剪枝

原代码把当前最远候选距离当成完整的 k 近邻半径，但候选少于 k 个时这个半径不足以排除另一侧。

已复现的反例：训练坐标 `[0, 1, 2, 3, 4]`，标签 `[1, 1, 1, 0, 0]`，查询坐标 4，k=5。原 KD 树只返回 `[4, 3, 2]` 三个邻居并预测 0，暴力法使用全部五个邻居预测 1。

建议把两处回溯判断都改为以下形式（还需结合下一项的等距离规则）：

```python
if len(knn_list) < k or abs(target[axis] - node.point[axis]) <= knn_list[-1][1]:
    rec(other_branch)
```

这里 `other_branch` 表示未优先访问的另一侧子树。已在内存副本上验证此条件能让上述反例返回 5 个邻居并预测 1；它没有应用到正式计时版本，也不代表完整修复已经验收。

### 6.2 统一距离相等及投票平局的规则

暴力法按训练文件顺序稳定排序，KD 树按节点访问顺序稳定排序。当第 k 个邻居附近存在等距离点时，两者可能选择不同标签。

已复现：坐标 `[-1, 1]`、标签 `[0, 1]`、查询 0、k=1，KD 树预测 1，暴力法预测 0；即使只修正上述剪枝条件，结果仍不同。

建议给训练点保存固定的原始行号，两种实现都用 `(距离, 原始行号)` 排序；搜索时允许检查与当前半径相等的另一侧，再由行号决定取舍。类别票数平局时也应明确采用固定类别顺序或其他确定性规则。修正后以暴力法为参照比较邻居行号和预测结果，加入重复坐标、等距离、k=1、k=n 等边界验证。

### 6.3 处理评估公式的零分母并校验输入

没有预测正例时，`TP + FP` 为 0；没有真实正例时，`TP + FN` 为 0；精确率和召回率均为 0 时，原 F1 公式也会除零。建议显式约定零分母结果，并保留提示：

```python
precision = tp / (tp + fp) if tp + fp else 0.0
recall = tp / (tp + fn) if tp + fn else 0.0
f1 = 2 * tp / (2 * tp + fp + fn) if 2 * tp + fp + fn else 0.0
```

同时校验训练集和测试集非空、特征与标签长度一致、`1 <= k <= 训练样本数`、每个向量维度一致、训练/测试表头一致、特征数量在有效范围内、数值没有缺失或非有限值。原 `zip` 会悄悄截断不等长输入，不能依靠它进行维度校验。

### 6.4 降低距离与候选维护的开销

- 仅比较远近时可比较平方距离，省去每个点的 `sqrt`；剪枝时也要同步使用“到分割面距离的平方”，不要混用两种单位。
- 暴力法不必对 n 个距离全部排序：维护大小为 k 的最大堆，或采用部分选择，降低候选筛选成本。
- KD 树当前每访问一个点就排序候选列表；k 较大时可换最大堆。当前 k=5 很小，是否更快仍应实测。
- 本实现建树在每个递归子问题上重新排序，时间上界为 O(n log² n)，还有列表切片开销；可考虑原地分区选中位数、减少复制。
- 暴力法单次查询成本约为 O(nd + n log n)；KD 树若访问 v 个节点，本实现约为 O(v(d + k log k))，最坏可能访问全部训练点。平衡树不等于查询一定只需 O(log n)。

### 6.5 改善特征处理和模型评估

- 仅在训练集上拟合标准化或归一化参数，再应用到验证集和测试集，避免信息泄漏；否则 BMI、天数等数值范围较大的列可能主导欧氏距离。二元、序数特征的处理应结合具体含义。
- 使用固定随机种子的分层抽样或合理的预先划分，不总是截取 CSV 前若干行。
- 除 Accuracy 外报告 Precision、Recall、F1、混淆矩阵及多数类基线，关注少数类效果。
- 用训练/验证划分或交叉验证选择 k、特征组合和距离加权方式，最后只用保留测试集报告结果。

### 6.6 改善实验可复现性和工程结构

- 使用 `time.perf_counter()`、重复测量并报告中位数和波动范围，分开记录训练、预测、总时间及每条样本耗时。
- 每次批量预测前清零 `visited` 或读取前后差值，避免同一棵树连续调用 `predict` 时混入上一次计数。
- CSV 加载可按需读取前 N 行，避免先加载整个数据集再丢弃；文件路径可基于 `Path(__file__).resolve().parent`，避免受工作目录影响。
- 将参数、模型实现、评价和实验记录分离，并持久化 CSV、配置、文件哈希和环境版本；本次配套记录脚本已实现其中的计时与留档部分。
